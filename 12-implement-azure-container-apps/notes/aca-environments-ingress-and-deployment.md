# Azure Container Apps – Environments, Ingress and Deployment

## Overview

Deploying an Azure Container App involves creating or selecting a Container Apps Environment, configuring the application container, setting ingress options, and verifying the application endpoint.

This document summarizes the deployment, networking, and application verification concepts covered in the lab.

## 1. Container Apps Environment Creation

The lab creates a new environment named:

`my-environment`

### Configuration

| Setting          | Value            |
| ---------------- | ---------------- |
| Resource group   | `az104-rg9`      |
| Environment name | `my-environment` |
| Region           | Central US       |

### Deployment Workflow

1. Open Azure Container Apps.
2. Select Create.
3. Choose Container App.
4. Configure the subscription.
5. Select the resource group.
6. Enter the application name.
7. Select the region.
8. Create a new Container Apps Environment.
9. Enter the environment name.
10. Create the environment.
11. Continue with container configuration.

A container image provides the application and dependencies required to run the container.

Quickstart images simplify the initial deployment process.

## 3. Application Ingress

Ingress controls how incoming network traffic reaches an application.

Azure Container Apps provides ingress configuration to manage application connectivity.

### Common Ingress Types

**External ingress**

Allows clients outside the Container Apps Environment to access the application through its configured endpoint.

**Internal ingress**

Restricts application access to the internal network environment.

### Important Considerations

* The selected ingress type affects application accessibility.
* External ingress is appropriate when an application must be accessed through its public endpoint.
* Internal ingress is useful for applications intended to communicate within a private environment.
* The application must listen on the configured target port.
* The original lab instructs configuring ingress as needed but does not specify every field value.

For this lab, record the actual ingress settings selected in Azure.

## 4. Application URL

Azure Container Apps can provide a DNS endpoint for an application with the appropriate ingress configuration.

The Application URL can be found on the Container App overview page.

### Verification Workflow

1. Open the Container App.
2. Navigate to Overview.
3. Locate Application URL.
4. Open the URL in a browser.
5. Verify that the application responds successfully.

The Application URL is generated by Azure and should be copied from the actual resource rather than constructed manually.

## 5. Application Port

The lab's sample application accepts traffic on port 80 by default.

Port 80 is the standard HTTP port.

The configured ingress target port must match the port on which the application listens.

If the ports do not match, application access may fail even if the container itself is running.

## 6. Application Verification

The expected response from the sample application is:

**Your container app is running with a Hello World image**

Successful access demonstrates that:

* The container app was deployed.
* The application started.
* The Application URL is available.
* Ingress allows the required traffic.
* The application is responding to browser requests.

## 7. Troubleshooting

### Environment Creation Failure

Check:

* Resource group.
* Subscription permissions.
* Selected region.
* Environment name.
* Deployment error details.
* Azure Activity Log.

### Container App Deployment Failure

Check:

* Container App name.
* Environment selection.
* Quickstart image selection.
* Deployment validation.
* Resource deployment status.

### Application URL Missing

Check:

* Container App deployment status.
* Ingress configuration.
* Application resource overview.
* Whether the application has completed deployment.

### Application Not Accessible

Check:

* Correct Application URL.
* External or internal ingress setting.
* Application target port.
* Container app deployment status.
* Application startup status.

If internal ingress is selected, direct access from a public browser may not work.

### Application Returns an Unexpected Response

Check:

* Container image.
* Application startup.
* Target port.
* Ingress configuration.
* Container app deployment details.

## 8. Security Considerations

* Expose only the application endpoints that are required.
* Use internal ingress for workloads that should not be publicly accessible.
* Use HTTPS for production application traffic.
* Avoid exposing administrative interfaces.
* Protect secrets and application configuration.
* Review network access requirements.
* Remove unused container apps and environments.

The lab is a simple HTTP demonstration. Production workloads should use appropriate secure communication and access controls.

## 9. AZ-104 Revision Points

* A Container Apps Environment hosts container apps.
* Container apps are deployed within an environment.
* Quickstart images simplify container deployment.
* Ingress controls incoming application traffic.
* External ingress permits access from outside the environment.
* Internal ingress limits access to the environment's internal network.
* Application URLs are provided by Azure for appropriately configured applications.
* The application target port must match the port used by the application.
* Port 80 is used by the sample application in this lab.
